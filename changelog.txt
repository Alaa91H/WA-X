WaEnhancer 1.6.2
Release date: 2026-10-04

HIGHLIGHTS
- Added support for WhatsApp 2.26.40.x and extended WhatsApp Business support to 2.26.39.x.
- Version detection now falls back to built-in supported-version lists when the resource arrays cannot be read, and logs the resolved list for diagnostics.
- Consolidated all build and release automation into a single hardened CI workflow.
- Added an automated baseline report and a merge-blocking regression gate for lint, unit tests, and APK size.

COMPATIBILITY
- WhatsApp: 2.26.32.x, 2.26.34.x, 2.26.35.x, 2.26.36.x, 2.26.37.x, 2.26.38.x, 2.26.39.x, and 2.26.40.x.
- WhatsApp Business: 2.26.32.x, 2.26.34.x, 2.26.35.x, 2.26.36.x, 2.26.37.x, 2.26.38.x, and 2.26.39.x.
- The module keeps starting when the supported-version resources fail to load instead of reporting a false incompatibility.

BUILD & RELEASE
- One workflow now owns the pipeline: build, unit tests, Android lint, baseline regression gate, APK preparation, signature verification, tag validation, and GitHub Release publishing.
- Normal runs build and sign debug APKs, keep them as CI artifacts for testing, and never publish a GitHub Release.
- Only version tags use the release keystore; release APKs are never signed with the debug key.
- The configured version must match the release tag in the form v<version>.
- Release assets are exactly two deterministic .apk files:
  - WaEnhancer-<version>.apk
  - WaEnhancer-Business-<version>.apk
- The regression gate compares each change against the baseline of the base revision, so a change cannot bypass the limits it is checked against by editing its own baseline.json.

DEVELOPER NOTES
- Gradle and Kotlin daemon JVMs now force the en-US locale, fixing local builds on non-English systems where Room code generation emitted localized digits.
- Shell scripts are checked out with LF line endings on every platform.
- The baseline generator records executed, skipped, failed, and errored unit tests from the JUnit XML output.
