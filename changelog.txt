WA X 1.2.0-beta.6
Release date: 2026-10-08

Development package 6: WA X features can now be written against something other than a
SharedPreferences object, and the first one has been rewritten that way. Nothing you can see
changed. The point of this build is that the next one can be tested.

THE THING THAT WAS WRONG
- Every feature in WA X extended one class whose constructor was a class loader and a
  SharedPreferences, and whose only method was doHook(), which returns nothing.
- Sixty-four features did that. Every one of them was constructed reflectively from those two
  arguments, so none of them could be given anything else: not a clock, not a logger, not a
  recording of what it hooked.
- The practical cost was that the entire feature layer had no unit tests at all - not a low
  number, zero. Twelve hundred and fifteen classes, no way to run any of them off a device.
- doHook() returning nothing was the other half of it. "I installed", "this build does not have
  the thing I hook", "I installed but half of it is unavailable" and "I failed" were the same
  event, and the only way to make any of them visible was to throw.

THE NEW CONTRACTS
- Nine contracts, in one package, that name no platform type at all: WaFeature, FeatureContext,
  FeatureStartResult, HookEngine, CapabilityProvider, DiagnosticSink, RuntimeClock, RuntimeLogger,
  and the settings snapshot that already existed.
- FeatureStartResult is the part worth noticing. Installed, degraded, skipped and failed are now
  four different answers, so a feature can say "this WhatsApp version does not have the hook I
  wanted" without pretending it succeeded and without crashing.
- A feature no longer receives preferences. It receives an immutable, target-scoped snapshot of
  the settings, so a test can hand it real settings over an in-memory store.
- A feature still gets the target's ClassLoader, because reflecting on the target's classes is
  the entire job - but it is handed to the feature rather than read from a global, so a test
  controls it.
- There is deliberately no Context. A feature that wants to show a dialog would be asking for
  something a module cannot honestly provide, and leaving that impossible is what keeps the rest
  of it testable.

THE PROOF, NOT THE PROMISE
- One real feature, taken straight from the shipped code, is now started in a plain JVM test with
  fakes and a real settings snapshot. No device. No framework. If that test compiles and passes,
  the claim holds, and CI runs it.
- A gate in CI fails if a platform type appears anywhere in that contract package - as an import or
  as a fully qualified name - and it fails if the contracts stop being implemented. A checker
  nobody runs is a comment, so it runs in every build from this one onwards.
- Test count: 1290, up from 1281. None failing.

WHAT DID NOT CHANGE
- Sixty-three of the sixty-four features still use the old contract, and WA X starts them exactly
  as it always has. One was migrated: the debug feature, chosen because it does nothing, so if the
  migration were wrong the only thing that could be wrong is the migration.
- Nothing on screen behaves differently. There is no new setting, and no feature was added, removed
  or changed.
- The boundary between the app's own code and the code that runs inside WhatsApp is unchanged and
  still has three known leaks. They are now filed with the exact files involved instead of being
  quietly counted.

UPGRADE
- Install over 1.2.0-beta.5. Same signature, so Android keeps the module's settings; nothing in
  this build migrates or rewrites anything you have configured.
